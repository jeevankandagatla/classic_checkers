2. PROJECT DESCRIPTION

Introduction to the Classic Checkers Game
Checkers (or Draughts) is a classic strategy board game played on an 8x8 grid. The digital version built during this internship replicates the physical experience, allowing two players to play locally on the same device. It strictly enforces standard checkers rules, making manual refereeing unnecessary.

Features of the Application
Player vs Player: Local multiplayer functionality.
Strict Move Validation: Prevents illegal moves and highlights available valid squares.
Forced Jumps: Enforces the rule that a player must capture an opponent's piece if possible.
Multi-Jumps: Allows consecutive captures in a single turn.
King Promotion: Automatically promotes pieces that reach the opponent's back rank.
Turn & History Tracking: Displays whose turn it is and maintains a log of past moves.
Minimalist UI: Features a warm, cream and dark-brown wooden board aesthetic.

Scope and Objectives
The scope of the project was strictly frontend-focused, ensuring an optimized and bug-free user experience in the browser without relying on external game engines. The core objective was mastering React state management while handling complex, branching game logic.

5. IMPLEMENTATION

Board Representation
The board is represented in state as an 8x8 2D array (or a flat 64-element array). Each element tracks the presence of a piece, the color of the piece, and whether it has been promoted to a King.

Move Validation
When a user clicks a piece, the game calculates all valid diagonal moves. It checks if the destination square is empty and if the path involves a valid step (1 square for regular moves, 2 squares for captures). 

Capture Mechanism
If an opponent's piece is located diagonally adjacent and the square behind it is empty, a jump is valid. The state is updated to remove the captured piece from the board representation array.

King Promotion
A check is performed at the end of every move. If a Red piece lands on row 0 or a Black piece lands on row 7, its isKing property is flagged as true, allowing it to move both forwards and backwards in future turns.

Turn Management
A state variable tracks currentPlayer. After a successful move (that doesn't result in an additional multi-jump), the turn is toggled, and the UI updates to notify the next player.

Win Detection
Before each turn, the game scans the board. If a player has no pieces remaining, or if they have pieces but zero valid legal moves available, the opposing player is declared the winner, and a Game Over screen is triggered.

User Interface
The UI was built with a warm palette reflecting a physical board. Click handlers on squares provide visual feedback, highlighting selected pieces and valid landing zones to improve user experience.


6. CHALLENGES FACED

Implementing Forced Jumps
Challenge: The standard rule dictates a player must capture if possible, which required scanning the entire board before a turn started to lock non-jumping pieces.
Solution: Implemented an algorithmic check at the start of each turn that flags available jumps and disables standard moves if a jump is detected.

Handling Multi-Jumps
Challenge: Allowing a player to jump again without passing the turn to the opponent was difficult to track in state.
Solution: Created a temporary "jumping" state. If a piece lands a jump and has another jump available, the turn does not toggle, and only that specific piece remains selectable.

Complex State Mutations in React
Challenge: Directly mutating the 2D array caused the React board component to fail to re-render.
Solution: Utilized deep copying (e.g., mapping arrays or using spread syntax) to ensure a completely new board object was passed to setState, triggering proper DOM updates.
